Ce qui rend cette automatisation fiable

Une donnée fausse arrête tout

Le chargeur refuse un prix négatif, un SKU en double ou une devise inconnue. Il protège aussi les 192 lignes « Amérique du Nord », dont le code NA disparaîtrait à la lecture sans ce réglage.

assert df["prix"].gt(0).all()

Les phrases suivent les chiffres

Ce que le site affirme est recalculé à chaque build. Si un import dément une phrase, elle se reformule au lieu de devenir fausse. Un fournisseur fictif vérifie ce comportement à chaque passage.

"chers_tous_illimites": bool(...)

Le contrôle porte sur la page réelle

Le vérificateur ne connaît aucune valeur attendue. Il compare le HTML qui sera servi aux JSON qui l'ont produit : un nouvel import ne le fait pas échouer à tort, et un site périmé ne passe pas.

dash.texte.includes(nu(d.pourquoi))

Le déroulé, étape par étape

  1. 01

    Fichier déposé. Déposer un fichier fournisseur dans le dépôt suffit. Une modification du code déclenche la même chaîne.

  2. 02

    Agréger. Un seul chargeur lit les 18 fichiers fournisseurs et produit les JSON du site. Les phrases sont recalculées avec les chiffres.

  3. 03

    Construire. Vite empaquette les JSON dans l'application, puis un fichier HTML complet est écrit pour chaque page.

  4. 04

    Vérifier. Le HTML qui sera servi est comparé aux données qui l'ont produit : chiffres, phrases, SEO, liens internes.

  5. 05

    Tester la prose. Un fournisseur fictif, construit pour démentir chaque affirmation, vérifie que les phrases changent de conclusion.

  6. 06

    Changement ?. Les rapports sont régénérés, puis le workflow compare le résultat à ce qui est déjà dans le dépôt.

  7. 07

    Commit automatique. Les JSON, le site et les rapports régénérés sont commités au nom du propriétaire du dépôt, puis poussés.

  8. 08

    Vercel. Le nouveau commit déclenche le déploiement. Vercel reconstruit le site à partir des JSON versionnés, sans Python.

  9. 09

    Site en ligne. Le tableau de bord et l'article affichent les nouvelles données, phrases comprises. Personne n'a touché au code.

Ce qu'elle ne fait pas encore

Les fichiers arrivent aujourd'hui par un commit dans le dépôt. Brancher une source réelle (mail, SFTP ou API d'un fournisseur) reviendrait à ajouter une étape en amont : tout ce qui suit fonctionne déjà. L'audit dans un vrai navigateur, lui, se lance à la main.

Comment ce tableau de bord est construit

Les 18 fichiers CSV sont agrégés en Python au moment du build, puis le résultat est empaqueté dans la page. Le navigateur ne lit jamais les CSV : il n'y a ni serveur, ni base de données, ni appel réseau. Sept assertions font échouer le build plutôt que de laisser passer un chiffre faux, notamment si les 192 lignes « Amérique du Nord » venaient à disparaître silencieusement.
